=== Relations

Relation calls are dispatched through the same layered chain as function calls:
the relation definition is resolved from the context, then evaluation is
dispatched based on whether the relation is extern or user-defined.

An entry point for relation calls is the following relation:

${relation-title-prose: Call_rel}
${rulegroup-prose: Call_rel}

The actual relation call is performed by the following relation, dispatching
according to the relation type. The relation definition is looked up in the
context and its kind determines which evaluation strategy is used.

${relation-title-prose: Call_rel_dispatch}
${rulegroup-prose: Call_rel_dispatch}

==== Extern relations

Extern relations are declared in the specification but implemented outside of
it, typically by the host environment or an architecture-specific model. The
specification defines only the signature; the implementation is invoked by the
interpreter's external dispatch mechanism.

${relation-title-prose: Call_extern_rel}

==== User-defined relations

A user-defined relation is defined by a collection of rule groups, optionally
followed by an else group. Calling a user-defined relation attempts each rule
group in order, trying all rule paths within the matched group, and returns the
first successful result. If no rule group matches, the else group is tried if
present; if none matches, the call fails.

${relation-title-prose: Call_defined_rel}
${rulegroup-prose: Call_defined_rel}

Rule groups are evaluated as follows. The list of rule groups is tried in
order; the first group whose match head (input patterns and guarding premises)
applies to the given inputs is evaluated. Within a matching group, the rule
paths are tried in order to find a successful result.

${relation-title-prose: Eval_rulgroups}
${rulegroup-prose: Eval_rulgroups}

${relation-title-prose: Eval_rulgroup}
${rulegroup-prose: Eval_rulgroup/succ}
${rulegroup-prose: Eval_rulgroup/fail}

Rules are evaluated as follows. Each rule path within a rule group is tried in
order. A rule path succeeds when its output expressions can be bound to the
values produced by its premises; the first successful path provides the result
for the entire rule group.

${relation-title-prose: Eval_ruls}
${rulegroup-prose: Eval_ruls}

${relation-title-prose: Eval_rul}
${rulegroup-prose: Eval_rul/succ}
${rulegroup-prose: Eval_rul/fail}
